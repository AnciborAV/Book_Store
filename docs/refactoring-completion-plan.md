# План завершения унификации и рефакторинга «Переплёта»

Дата инвентаризации: 1 ноября 2026 года. База: `e181bf5d39a4383ee40f36276f878b8335de3a48`, master после принятого PR №86. Платформа остаётся Java 21.

## Область и результат

Закрытый перечень файлов находится в [refactoring-inventory.csv](refactoring-inventory.csv): 254 строки с путём, группой, статусом, причиной проверки и исходным Git SHA. В нём 69 Java-файлов приложения, 46 собственных JS-модулей, 22 CSS-файла, 14 HTML-страниц, 42 Java-файла тестов, 23 скрипта, 7 конфигурационных файлов и 31 файл миграций/их данных. Последние включены для явной фиксации исключения из форматирования.

Цель этого цикла: единое читаемое оформление собственного кода и проверенные границы уже выделенных компонентов. Существующие API, поведение, данные, пользовательские тексты и оформление сайта сохраняются. Новые функции, изменение модели корзины, перенос гостевого выбора, миграция Java и переписывание архитектуры целиком в этот цикл не входят.

Обзорные признаки плотного кода использованы для приоритизации: длинные строки вне обычных строковых литералов, несколько действий в строке, короткие условия и импорты со звёздочкой. Статус «унифицировать» является кандидатом на небольшую правку, а не оценкой функциональной исправности файла. «Контрольная проверка» требует просмотра общих правил и может закончиться без редактирования. Метрики заполнены для основных Java/JS/CSS; вспомогательные файлы пока только перечислены. Это инвентаризация, а не утверждение о построчном аудите всех 254 файлов.

## Общие правила

- Основа: существующий `.editorconfig`, UTF-8, LF, завершающий перевод строки, отсутствие хвостовых пробелов. Java и Python: 4 пробела; JS/CJS/MJS, HTML, CSS, JSON и YAML: 2. Сейчас MJS не входит в маску `.editorconfig`; эту маску нужно дополнить отдельно в группе Q2.
- Java: упорядоченные явные импорты, отдельные объявления/действия, фигурные скобки у условий и циклов, читаемые сигнатуры и аргументы; публичные методы перед приватными вспомогательными, если это помогает читать класс. Порядок полей конструктора, компонентов record, аннотаций с поведением и статической инициализации сохраняется.
- JS: одинаковые отступы, явные блоки и читаемые обработчики; обычные строки приводятся к двойным кавычкам с сохранением значения. Шаблонные строки HTML и текстов сохраняются без изменения содержимого. Порядок событий, await, запросов, ошибок и обновлений DOM не меняется ради оформления.
- Ориентир длины строки кода: 120 символов. SQL, HTML-шаблоны, регулярные выражения, сообщения и данные не дробятся автоматически ради этого ограничения. Для них важнее точное сохранение содержимого.
- CSS: читаемые правила, прежний порядок селекторов и объявлений, специфичность и медиазапросы. Перестановка правил, удаление «дублей» и переименование классов требуют отдельного доказательства эквивалентности.
- Существующие SQL, HTTP-методы/маршруты, DTO, права, CSRF, remember-me, транзакции, версии, блокировки, суммы и размеры файловых блоков сохраняются. Изменение такого поведения оформляется отдельной задачей.

## Что сохраняется без форматирования

Три JS-файла данных атласов (DATA), 31 файл исторических миграций и их данных (MIGRATIONS), опубликованные тексты/биографии/описания в JSON и шаблонах, изображения/PDF, сторонний PDF.js и Maven Wrapper. Исторические миграции нельзя переписывать ради стиля: это затрагивает контрольные суммы Liquibase. Для новых SQL/миграций действуют обычные отдельные проверки, но они не являются задачей этого цикла.

## Проверка каждого PR

1. Выбрать один небольшой участок и записать его группу/файлы. При обнаружении функциональной проблемы зарегистрировать её отдельно и не смешивать со стилем.
2. Запустить существующие целевые проверки на исходной версии; после правки повторить тот же набор. Для простого оформления новых тестов не требуется. Если выделяются обязанности или затрагивается недостаточно покрытый сценарий, сначала добавить осмысленную проверку прежнего поведения.
3. Сопоставить операции, значения строк/шаблонов, SQL и аннотации, если они затронуты; для переносов методов проверить конструктор и статическую инициализацию. При необходимости использовать сравнение скомпилированных инструкций, не заявляя побайтовую идентичность class-файлов.
4. Для JS/CSS/HTML проверить изменённые пользовательские действия. Визуальная область требует сравнения до/после. Если локальная среда запрещает сервер, использовать изолированный CI и его артефакты, явно указав границу проверки.
5. Обновить строку реестра, ссылку на PR/проверку и запись в refactoring.md. Не запускать следующий блок до фиксации результата текущего. Рабочую базу и реальные заказы для тестов не использовать.

## Критерий завершения

Цикл завершён, когда у каждой строки реестра есть окончательный статус «готово», «проверено без правки» либо «исключено» с причиной; все введённые при работе собственные файлы учтены. Для закрытых файлов указаны PR или результат контрольной проверки. Не остаётся открытых обязательных пунктов по общим правилам, регрессий и красных обязательных проверок на итоговом SHA.

Финальный CI выполняет полный серверный прогон с PostgreSQL, все подключённые клиентские проверки и оба браузерных сценария: регистрация/вход, каталог/полка, корзина, заказ/склад/перезапуск, PDF, административные действия. Число тестов фиксируется по фактическому результату, а не принимается равным прежним 186/56. Финальный обзор также подтверждает отсутствие ненамеренных изменений UI, пользовательских текстов, схемы базы и платформы Java 21.

После этого фиксируется завершение именно данного перечня. Новые функции, нагрузочные испытания и независимый аудит безопасности остаются отдельными работами. Дополнительные идеи улучшений не расширяют этот цикл автоматически.
