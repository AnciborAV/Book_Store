# Электронная библиотека Java

В каталоге выберите «Java · PDF». Список, обложки и скачивание доступны без входа.
Администратору видна кнопка «Добавить PDF». Обязательны название и PDF; автор,
описание и отдельная обложка необязательны. Книга публикуется сразу после успешного сохранения.

- PDF до 500 МБ, без пароля. Число книг не ограничено программным лимитом.
- По умолчанию обложка получается из первой страницы PDF, без обрезки.
- Можно загрузить свою PNG/JPEG до 2 МБ и 4096 × 4096; пропорции сохраняются.
- «Редактировать» позволяет менять метаданные и файлы. Пустые поля выбора файла
  сохраняют существующие файлы. Новый PDF получает новую обложку первой страницы,
  если не передана отдельная. Исходный PDF хранится и скачивается байт-в-байт.
- «Удалить» после подтверждения удаляет запись, PDF и обложку. Уже скачанные копии
  на устройствах посетителей удалить невозможно.

## Хранение и запуск

Миграция `java-library.xml` добавляет метаданные в `java_library` и двоичные файлы
в `java_library_files` (обложка) и `java_library_pdf_chunks` (PDF блоками по 1 МБ, PostgreSQL BYTEA). Файлы не зависят от
временного диска Render. Они входят в резервную копию БД. Списки запрашивают только
метаданные, по 12 книг; поиск выполняется на сервере. Физический предел библиотеки
определяется доступным хранилищем БД. Бесплатная база Render не является бессрочным
или безразмерным хранилищем: для большой коллекции потребуется больше места и
резервное копирование, в дальнейшем — объектное хранилище.

Общий multipart-предел повышен до 500 МБ на файл / 504 МБ на запрос. Проверка аватарок
по-прежнему ограничивает их 2 МБ. PDF и изображения проверяются сервером. Для
экономии памяти одновременно выполняется одна операция подготовки файлов; при
занятости администратор получает 429 и может повторить запрос. PDF временно размещается на диске для проверки и извлечения первой страницы;
после сохранения временный файл удаляется. Чтение PDFBox использует файловый доступ
и дисковый кэш. Сохранение и скачивание работают блоками по 1 МБ. Скачивание ведётся
в транзакции REPEATABLE_READ: замена книги не смешивает старые и новые блоки.
Это экономит память, но большие файлы всё равно занимают место БД и ресурсы сервера.
Загрузка не возобновляется с места обрыва: при потере соединения её нужно повторить.

Изменения разрешены только `/api/admin/java-library/**` с ADMIN и CSRF-токеном.
Версия записи защищает от перезаписи изменений из устаревшей формы. PDF отдается
как attachment, не встраивается в страницу. Первую страницу визуализирует PDFBox 3.0.8;
исходный документ не преобразуется. Для выкладки применяется обычный merge PR и
деплой Render, миграция выполняется при запуске. Секреты и новые переменные не нужны.

## Проверки

`JavaLibraryTest`, `PostgresJavaLibraryTest` проверяют доступы, CSRF, исходные байты,
пропорции обложек, редактирование, удаление файлов каскадом, устаревшую версию,
некорректные PDF, поиск и переход на следующую страницу. Браузерный сценарий
`scripts/java-library-smoke.cjs` проверяет загрузку через форму, редактирование,
анонимное скачивание и сохранность после перезапуска файловой H2, размеры 1440/390.
