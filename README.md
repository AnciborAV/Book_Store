# Book Store — «Переплёт»

Локальный книжный каталог на Java 17, Spring Boot, PostgreSQL и Liquibase.
Приложение открывается на **http://localhost:8080/**. По умолчанию сервер слушает
только `127.0.0.1`: публикация в интернет не выполняется.

## Возможности

- Регистрация, вход по email, выход и сессионная авторизация.
- Профиль и загрузка PNG/JPEG-аватарки до 2 МБ и 4096×4096 пикселей.
- Каталог: добавление после входа, серверный поиск, страницы по 12 книг.
- Личная полка в базе: доступна после повторного входа с другого браузера.
- Полка, аккаунты и книги сохраняются после перезапуска приложения.
- Адаптивный интерфейс, состояния загрузки, пустого каталога и ошибок.

Это каталог и личные подборки, а не система продажи: цены, оплата, заказы и PDF
не входят в текущую реализацию. Любой зарегистрированный пользователь может
пополнять общий каталог. Название книги уникально — сохранено исходное правило
базы. Разные издания одной книги потребуют отдельной модели изданий и ISBN.

## Запуск с PostgreSQL — основной вариант

Нужны JDK 17 и установленная PostgreSQL. Maven установит Wrapper.
Создайте отдельного пользователя и базу в psql (пароль задайте свой):

```sql
CREATE USER bookstore WITH PASSWORD 'replace-with-your-own-password';
CREATE DATABASE books OWNER bookstore;
```

В терминале macOS/Linux в папке проекта:

```sh
export DB_URL='jdbc:postgresql://localhost:5432/books'
export DB_USERNAME='bookstore'
read -s DB_PASSWORD
export DB_PASSWORD
./mvnw spring-boot:run
```

После команды `read` введите пароль базы и нажмите Enter: он не отображается.
Не сохраняйте пароль в исходниках. После сообщения о запуске Tomcat откройте
http://localhost:8080/ и нажмите «Войти → Зарегистрироваться».

Пароль аккаунта задаётся самостоятельно: от 8 символов, не более 72 байт UTF-8.
Пароль базы и пароль аккаунта — разные настройки. Готовых аккаунтов и паролей нет.
Liquibase применяет миграции, Hibernate проверяет соответствие схемы модели.
При ошибке подключения проверьте работающую PostgreSQL, имя базы и переменные.

## IntelliJ IDEA

1. Откройте корневой `pom.xml` как Maven-проект, дождитесь загрузки зависимостей.
2. Выберите JDK 17 для Project SDK и Maven Runner.
3. Откройте `ru.aav.BookStoreDemoApplication` и создайте конфигурацию запуска.
4. В Environment variables задайте `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`.
5. Запустите `main`, откройте http://localhost:8080/.

## Быстрый запуск без PostgreSQL

Для отдельной демонстрации есть файловая H2. Это **другая база**, данные из
PostgreSQL автоматически в неё не переносятся:

```sh
./mvnw spring-boot:run -Dspring-boot.run.profiles=local
```

В IntelliJ вместо переменных базы задайте VM option `-Dspring.profiles.active=local`.
H2 хранится в `data/` относительно рабочего каталога. Не удаляйте эту папку,
если хотите сохранить данные. Не запускайте две копии приложения с одной H2.

Чтобы изменить занятый порт, задайте `SERVER_PORT=8081` и откройте этот порт.
Для остановки используйте Stop в IDEA или Ctrl+C в терминале.

## Архитектура

Приложение — небольшой модульный монолит. Внутри каждого сценария используются
HTTP-контроллер → транзакционный сервис → репозиторий.

| Пакет | Ответственность |
|---|---|
| `controller`, `service`, `repository`, `model`, `mapper` | Каталог, DTO, MapStruct и JPA |
| `auth` | Регистрация, нормализация email, BCrypt, учётные записи |
| `profile` | Профиль и обработка аватарок |
| `shelf` | Личная полка с обязательным ограничением по владельцу |
| `config` | Spring Security и единая обработка ошибок |

Контроллеры не обрабатывают изображения и не работают с репозиториями напрямую.
Изображение проверяется до полной декодировки, обрезается и заново кодируется в
PNG 256×256. Пароли и JPA-сущности пользователей не выдаются в API.
Все изменения требуют CSRF-токен и, кроме регистрации/входа, авторизованную сессию.
Идентификатор владельца берётся из сессии, не из тела запроса.

Интерфейс — статические HTML/CSS и JavaScript, общающийся с REST API, **не Thymeleaf**.
Пользовательский текст выводится через `textContent`. Шрифты Google Fonts опциональны:
без интернета используются системные шрифты.

## API

| Метод и адрес | Назначение |
|---|---|
| `GET /books/page?query=java&page=0&size=12` | Поиск, размер страницы 1–100 |
| `GET /books/page?favorites=true` | Поиск на своей полке после входа |
| `GET /books` | Прежний API списка, оставлен для совместимости; веб-интерфейс его не использует |
| `GET /books/{id}` | Книга либо 404 |
| `POST /books` | Добавление `{ "name": "Java", "author": "Author" }` после входа |
| `GET /api/auth/csrf` | CSRF-токен и имя заголовка |
| `POST /api/auth/register` | JSON: email, displayName, password |
| `POST /api/auth/login` | Form: email, password |
| `POST /api/auth/logout` | Завершение сессии |
| `GET /api/profile` | Свой профиль |
| `GET /api/profile/avatar` | Своя аватарка |
| `PUT /api/profile/avatar` | Multipart, поле `file` |
| `GET /api/shelf` | ID книг своей полки |
| `PUT /api/shelf/{bookId}` | Добавление на полку |
| `DELETE /api/shelf/{bookId}` | Удаление с полки |

Ответ поиска: `{ "items": [], "total": 0, "pages": 0, "page": 0 }`.
Повторное последовательное добавление на полку безопасно; одновременные запросы
разрешает уникальное ограничение базы, возможен ответ 409 без дублирования данных.
Браузерная полка старой версии из localStorage автоматически не импортируется.

## Проверки

Полная сборка с интеграционными тестами требует Docker:

```sh
./mvnw clean verify
```

Тесты запускают собственные PostgreSQL-контейнеры и не используют вашу базу.
Без Docker доступны H2-сценарии и проверка маппинга:

```sh
./mvnw -Dtest=BookMapperTest,ProfileControllerTest,ShelfControllerTest test
```

GitHub Actions также запускает настоящий JAR на localhost, проверяет в Chromium
регистрацию, добавление книги, полку, перезапуск и повторный вход, выход и ширину
страниц на desktop/mobile. Отчёты, серверный журнал и снимки находятся в артефакте
`verification`. Подробности — в `VERIFICATION.md`.

Перед внешней публикацией нужен отдельный этап: роли администратора, HTTPS,
защита входа от перебора, восстановление доступа, мониторинг и резервные копии.
