01 / ДО ПРИВЫЧНЫХ ЯЗЫКОВ

Сначала нужно было
научиться задавать порядок.

1843

Замысел программы

В примечаниях Ады Лавлейс к описанию аналитической машины Бэббиджа появляется таблица вычисления чисел Бернулли. Машина тогда не была построена, поэтому это проект вычисления, а не выполненная компьютерная программа.

1936

Модель вычисления

Алан Тьюринг исследует формальное выполнение инструкций и пределы вычислимости. Машина Тьюринга является математической моделью, а не языком прикладной разработки.

1940-е

От схемы к памяти

Первые электронные машины программируют через устройства управления, коммутацию и машинные команды. Параллельно Конрад Цузе разрабатывает Plankalkül, но его идеи не становятся тогда массовым рабочим языком.

1948 / 1949

Программа хранится в машине

Manchester Baby выполняет программу в памяти в июне 1948 года. В мае 1949-го начинает работать кембриджский EDSAC. Следующий важный шаг состоит в том, чтобы облегчить не только выполнение, но и запись программы.

ИЗ АРХИВА / EDSAC

Три строки из 1949 года

Фрагмент опубликованного Кембриджем листинга программы квадратов Мориса Уилкса, датированной июнем 1949 года. Это отдельный документ, который не следует смешивать с первым успешным запуском 6 мая.

T123S сохраняет аккумулятор в ячейке 123 и очищает аккумуляторные регистры. E84S передаёт управление на позицию 84 при неотрицательном значении аккумулятора. PS здесь задаёт слово данных с нулём.

03 / МАСТЕРСКАЯ МАШИННОГО КОДА

Что происходит
между 2 + 3 и числом 5?

Проследите шесть инструкций MOS 6502, процессора 1975 года. Это более поздняя и компактная архитектура, удобная для знакомства с низким уровнем. Пример не выдаётся за первую программу в истории.

АДРЕС / БАЙТЫ / КОМАНДА6502 · учебная модель
    PC / следующий адрес$0600
    A / аккумулятор0
    C / перенос1
    D / десятичный режим1
    ПАМЯТЬ / $0010000000000

    Начальные значения для демонстрации: A = 0, C = 1, D = 1. Первые команды явно устанавливают нужные режимы.

    Почему здесь важны режим, перенос и последняя команда?

    ADC складывает значение аккумулятора, операнд и флаг переноса. Поэтому CLC очищает перенос перед сложением. CLD выбирает двоичную арифметику вместо десятичного режима.

    BRK у реального 6502 вызывает программное прерывание и использует стек и вектор обработчика. В этой учебной модели показаны только A, C, D, адрес следующей инструкции и одна ячейка памяти; на BRK разбор останавливается. Это не полноценный эмулятор процессора и не средство запуска произвольного кода.

    Источник системы команд: руководство семейства MCS6500, переиздание документации MOS Technology.

    ДРУГИЕ ВЕТВИ

    За пределами основной карты

    Это не список «незначительных» языков. Здесь собраны другие влиятельные традиции, специализированные инструменты и менее распространённые направления, которые требуют отдельного разговора.

    Функции, макросы, композиция

    Scheme, Racket, Clojure, F#, Elixir. Семейства различаются по типам, модели выполнения и отношению к изменяемому состоянию.

    Компактность и встраивание

    Forth, APL, Lua, Nim, Zig, Crystal. Среди них есть и языки со значительной промышленной историей, и более новые эксперименты.

    Платформы и прикладные среды

    Objective-C, Object Pascal / Delphi, Visual Basic, Groovy, PowerShell. Их роль часто определяется большой экосистемой существующего программного обеспечения.

    Особые предметные области

    Verilog и VHDL описывают цифровую аппаратуру; Solidity применяется для смарт-контрактов; Q# предназначен для квантовых алгоритмов. Их нельзя оценивать только по задачам обычного сайта.

    А где HTML, CSS и WebAssembly?

    HTML описывает структуру документа, CSS его представление. Они необходимы вебу, но их назначение отличается от универсального прикладного программирования.

    WebAssembly является форматом инструкций и целью компиляции, а не очередным высокоуровневым языком вместо JavaScript. Программу для него можно получать из разных языков; доступ к окружению зависит от среды выполнения.

    05 / ГОРИЗОНТ РАЗВИТИЯ

    Будущее складывается
    из нескольких направлений.

    Срез на 31 октября 2026 года. Ниже разделены уже существующие возможности и направления дальнейшего развития. Здесь нет обещания, что один язык вытеснит остальные.

    01 / ПАМЯТЬ

    Больше гарантий до запуска

    Уже существует: владение и заимствование Rust, проверяемые ограничения типов, статические анализаторы.

    Направление: сокращать число ошибок времени жизни и постепенно улучшать безопасность больших существующих систем. Одного нового синтаксиса для этого недостаточно.

    02 / КОНКУРЕНТНОСТЬ

    Задачи легче создавать, важнее завершать

    Уже существует: процессы Erlang, горутины Go, async/await и виртуальные потоки Java, окончательно включённые в Java 21.

    Направление: яснее выражать отмену, границы задачи и управление ресурсами. Простота запуска не устраняет гонки и взаимные блокировки.

    03 / ТИПЫ

    Модель данных ближе к задаче

    Уже существует: вывод типов, nullable-типы, перечисления с данными и сопоставление с образцом в разных языках.

    Направление: раньше обнаруживать противоречия и точнее описывать допустимые состояния, сохраняя понятность повседневного кода.

    04 / СОСУЩЕСТВОВАНИЕ

    Система говорит на нескольких языках

    Уже существует: Python вызывает нативные численные библиотеки, Java и Kotlin работают рядом в JVM, SQL обслуживает данные приложения.

    Направление: улучшать межъязыковые интерфейсы и переносимость. WebAssembly расширяет варианты исполнения, но не отменяет различий платформ.

    05 / ОБОРУДОВАНИЕ

    Данные движутся к ускорителю

    Уже существует: GPU-библиотеки, специализированные ядра и векторные операции.

    Направление: удобнее описывать вычисление и размещение данных. Знакомый высокоуровневый код может скрывать сложную цепочку компиляторов и устройств.

    06 / JAVA

    Развитие без разрыва экосистемы

    Уже существует: записи record, лямбда-выражения, сопоставление с образцом и виртуальные потоки.

    Направление: проекты OpenJDK исследуют более эффективные модели данных и дальнейшее упрощение конкурентного кода. Включение конкретной возможности зависит от принятой спецификации, а не от календарного обещания.

    07 / AI И ИНСТРУМЕНТЫ

    Код писать проще, проверять важнее

    Уже существует: генерация фрагментов кода и помощь в поиске объяснений.

    Направление: связывать помощника с тестами, анализом и проверяемым контекстом проекта. Сгенерированный текст не заменяет понимание требований, архитектуры и ответственности за результат.

    08 / НАСЛЕДИЕ

    Старый код продолжит жить рядом с новым

    Уже существует: важные системы на C, COBOL и Fortran и современные средства их сопровождения.

    Направление: обновлять постепенно, сохраняя проверенное поведение. Возраст языка сам по себе не определяет ни качество системы, ни стоимость её замены.

    Выбирайте не победителя, а подходящий инструмент.

    Начните с задачи, среды, доступных библиотек и опыта команды. Изучение второго языка ценно уже тем, что помогает иначе увидеть первый. Для Java-разработчика знакомство с Lisp, SQL или Rust может оказаться способом точнее мыслить о собственном коде.
